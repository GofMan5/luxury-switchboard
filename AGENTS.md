# Engineering contract

## Product bar

- Весь код обязан быть качественным, производительным, понятным и пригодным для production. Никакой халтуры, временных заглушек и скрытых нерабочих контролов.
- Интерфейс обязан быть красивым, спокойным, визуально цельным, удобным мышью и клавиатурой, адаптивным от компактного окна до большого экрана.
- Пользовательский сценарий важнее внутренней демонстрации технологий: меньше действий, ясные названия, предсказуемые состояния, быстрый feedback.
- Секреты, ключи, proxy credentials, SSH identity и тела запросов не попадают в UI, логи, crash reports, публичный tunnel или git. Доверенный owner-only экран Providers может показывать настроенный alias/endpoint для управления, но публичный tunnel, telemetry, client UI и shared control никогда не получают provider metadata или upstream URL; credential после записи не отражается обратно даже владельцу.

## Architecture: no monoliths

- Никаких монолитов, god-object, god-store, глобального mutable state, файлов-свалок и классов/пакетов, которые одновременно владеют несколькими независимыми сценариями.
- Искусственного ограничения по числу строк нет. Монолит определяется смешением ответственностей, высокой связностью, fan-in/fan-out и невозможностью независимо тестировать сценарий, а не длиной файла. Не дробить цельный код только ради метрики строк.
- Frontend и backend строятся независимо по hexagonal architecture и vertical slices.
- Каждый пользовательский сценарий содержит собственные domain/application/ports/adapters. UI, Tauri, HTTP, stdio, SQLite, SSH и файловая система являются внешними адаптерами.
- Зависимости направлены внутрь: adapters -> application -> domain. Domain не импортирует framework, transport, storage или UI.
- Связь между slices только через маленькие типизированные ports/contracts или явно определённые domain events. Запрещены неявные циклические зависимости и доступ к внутренностям соседнего slice.
- Общий код выносится только после реального повторения. Не создавать speculative abstraction, универсальный framework внутри проекта или wrapper без самостоятельной ответственности.
- Composition root только собирает зависимости и lifecycle; бизнес-логика в нём запрещена.

## Target runtime

- Backend и relay реализуются на Go. Он владеет routing, provider/key pools, RPM queues, retries, streaming, persistence, tunnel control, privacy и telemetry.
- Tauri v2 — тонкая desktop-оболочка. Rust-код содержит только обязательный lifecycle/sidecar bridge и не дублирует Go domain logic.
- Go sidecar общается с Tauri через версионированный stdio protocol. `stdout` зарезервирован только под framed protocol; диагностические логи идут в `stderr`.
- Каждая команда имеет correlation id, typed payload/result, terminal outcome и cancellation. Потоки обязаны поддерживать backpressure, bounded buffers и корректное завершение при shutdown/restart.
- Transport contracts валидируются на обеих сторонах. Неизвестная версия, malformed frame и oversized payload завершаются контролируемой ошибкой без зависания и утечки данных.

## Fast, deliberate delivery

- Не выполнять тупые действия, которые замедляют обновления без измеримой пользы: бессмысленные полные rebuild, повтор одинаковых тестов, последовательный запуск независимых проверок, лишние генераторы, ручное копирование boilerplate и ненужные зависимости запрещены.
- Сначала запускать минимальный targeted test/benchmark затронутого slice. Широкую матрицу запускать один раз на стабильном milestone или когда изменена публичная граница, schema, dependency, security boundary либо соседний тест упал.
- Независимые проверки выполнять параллельно. Использовать incremental build/cache и не инвалидировать их без причины.
- Оптимизация подтверждается профилем, benchmark или измерением latency/memory/allocations. Не усложнять код ради предполагаемой производительности.
- Hot paths не блокируют UI: никакого sync I/O, unbounded queue, busy loop, polling без backoff или полного rerender больших списков.
- Обновление должно быть атомарным и откатываемым. Старый рабочий Python relay хранится в `old-backup/python-relay` и не изменяется при разработке новой версии.

## Configuration-first product

- Минимум operational hardcode. Listener port, provider profile/dialect, endpoint, auth scheme/header, RPM, queue, timeouts, retry/heartbeat, cache, persistence/retention, routes and tunnel limits имеют валидируемые defaults и настраиваются через понятный Settings/UI contract.
- Hardcoded остаются только security invariants и абсолютные safety caps: loopback listener, remote HTTPS, bounded memory/frame/body, forbidden headers, secret redaction и fail-closed tunnel privacy. UI не позволяет ослабить эти границы до небезопасного состояния.
- Settings — отдельный vertical slice с typed schema, versioned migration, atomic encrypted persistence и preview/validation до commit. Никаких `map[string]any` или разбросанных env reads внутри domain/application.
- Любой OpenAI/Anthropic-compatible provider подключается typed profile: dialect, base URL, discovery/health paths, auth mode/header, cache/retry/timeouts and keys. Provider-specific workaround живёт в adapter/profile, а не в общей relay domain logic.
- Relay routes и public Tunnel routes независимы. Tunnel публикует только owner-defined aliases; raw upstream model ID, provider ID/name/URL, auth header и `owned_by` запрещены на public boundary.

## Frontend quality

- Frontend организован по feature slices; app shell только композирует navigation, layout и lifecycle.
- Состояние локально сценарию. Частые live updates не должны перерисовывать всё приложение; использовать selectors, batching, virtualization и bounded history там, где это измеримо нужно.
- Дизайн строится из единой системы tokens: neutral grey palette, typography, spacing, density, borders, radii, semantic status colors, focus, disabled и motion states.
- Все вкладки и модалки проверяются минимум в compact, standard и wide layouts. Никаких обрезанных кнопок, наложений, горизонтального overflow основных сценариев и нечитаемых таблиц.
- Все интерактивные элементы имеют hover/focus/pressed/disabled/loading/error states, понятную подпись и доступную keyboard navigation. Двойной клик не может быть единственным способом открыть важное действие.
- Анимация объясняет изменение состояния и уважает `prefers-reduced-motion`; декоративный шум, glow, gradient abuse, псевдо-AI эстетика и случайные карточки запрещены.
- Ни одна вкладка не имеет права утащить окно за собой. React при исключении на рендере размонтирует всё дерево, а boundary в приложении не было ни одного: одна запись без поля, которое читает ячейка, оставляла пустое окно без навигации — выйти можно было только закрыв приложение. `WorkspaceBoundary` стоит вокруг рабочей области, а не вокруг shell'а, именно поэтому: sidebar обязан выжить, потому что уход с битого экрана и есть способ восстановления. Второй способ — сама навигация, и она работает через `key={route}` в `AppShell`: React выбрасывает упавший экземпляр, вместо того чтобы класс сам сравнивал предыдущие props (`setState` в `componentDidUpdate` линтер запрещает, и по делу). Fallback сообщает, что экран не отобразился, и больше ничего: текст был бы провайдерский или из записи, а приложение осторожно с тем, что пересказывает; подробности уходят в консоль владельца. Проверяется на реальной оболочке записью без `count` (`keeps the shell alive when a workspace throws, and clears on navigation`) — тремя мутациями: без boundary, с постоянным `key` и без сброса.

## Backend reliability and privacy

- Retry policy классифицирует transport, 429, 5xx, permanent request errors и terminal stream outcomes. Нельзя бесконечно повторять заведомо permanent ошибку или выдавать оборванный stream без terminal event.
- Очереди RPM справедливые, отменяемые и наблюдаемые; неограниченное ожидание не означает неограниченное потребление памяти.
- При смене provider все старые запросы получают cancellation и освобождают sockets/leases/queue slots.
- Трансляция в Chat Completions обязана конвертировать, а не выбрасывать: freeform `custom` tool и его replayed history (`custom_tool_call`, `custom_tool_call_output`) уходят документированной функцией, иначе модель на chat-only провайдере снова начнёт пересказывать вызовы вместо их выполнения. Переписывание пути запроса на лету (проба endpoint'а) меняет цель, но не диалект: клиенту отвечают в том, в котором он открыл соединение, поэтому upstream-запрос всегда получает собственный `*url.URL`.
- Обратная трансляция — тоже конвертация, и «не выбрасывать» здесь про причину остановки. Chat говорит `finish_reason` и `refusal`, у Responses под каждое своё место, и всё три вида «ответа нет» раньше терялись: отказ приходил как `"status":"completed"` с пустым `output` (то есть провайдер якобы промолчал), фильтр — так же, а обрезанный по бюджету ответ — половиной фразы со штампом complete. Теперь отказ несётся текстом сообщения (у Responses нет своего поля на текстовой части, а пустой ответ клиенту не говорит ничего — и это текст, который ещё и guardrail прочитает), `length`/`content_filter` дают `status:"incomplete"` + `incomplete_details.reason`, а стрим закрывается `response.incomplete`, чтобы клиент, который смотрит на тип события, приходил к тому же выводу. Незнакомая причина не угадывается. Побочно это закрывает расхождение политик, и расхождение было в пользу chat: публичный tunnel считает `incomplete` небезопасным (`failedValue`) и такой ответ не отдаёт — нативный Responses-провайдер под это правило попадал, а chat-only проскакивал. Наблюдаемое следствие измерено: публичный клиент на chat-only провайдере вместо половины фразы теперь получает нейтральное «недоступно», как и на нативном. Это выравнивание, а не новая политика: если половину ответа отдавать всё-таки надо, менять надо `failedValue` для обоих видов провайдеров, а не оставлять дырку, которая случайно есть только у одного. `TestAChatProviderThatDidNotFinishSaysSoAfterTranslation` (шесть причин, каждая мутацией).
- Одно SSE-событие имеет право разложить свой JSON на несколько `data:`-строк — W3C склеивает их через `\n`. Так их читает `sseInspector`, так их читает и экстрактор guardrails, а вот починка tool calls такой блок раньше **не понимала и пропускала целиком**: item оставался объявленным как `completed` (клиент выбрасывал все его дельты), tool сохранял провайдерский алиас (клиент отвергал вызов, которого не объявлял), а пролог синтезировался поверх уже присланного объявления, потому что объявление не распозналось. Теперь строки склеиваются перед разбором, и результат байт-в-байт совпадает с однострочной формой — это и есть утверждение теста (`TestAnEventSplitAcrossDataLinesIsRepairedLikeAnyOther`), потому что фрейминг не должен решать, что делает починка. Разделитель именно `\n`: split, попавший внутрь строкового литерала, валиден только с ним, а склейка вплотную дала бы событие, которое сам клиент считает битым, — и relay успел бы наобъявлять item'ов под текст, который никто не прочитает (`TestDataLinesAreJoinedWithTheNewlineTheSpecNames`).
- Маркер и секрет — не одно и то же, хотя приходят одним списком. Санитайзер считает секретом всё, что получил: маркер, переживший редакцию, отказывает ответ целиком. Для credential это верно при любой длине, для идентификатора длиной 2–3 символа — катастрофа: заменить его в обычной прозе нельзя (`replace` требует ≥4), а `contains` его проверял, поэтому он мог только отвергать. Замерено: валидация провайдера принимает `https://ai/v1`, `https://llm:8080/v1` и `http://[::1]:8080/v1` (single-label alias и две обычные формы Docker-сервиса), `o3` — реальный upstream-модель id, а `socks5://tor:9050` — обычное имя контейнера, дающее маркер «tor» внутри constructor/monitor/iterator/vector/editor. Такие маркеры отказывали каждый ответ — неотличимо от недоступного провайдера и без единого слова на экране. Ширина `relayapp.MinRedactableMarkerBytes` (=4) названа один раз в `relay/application` (publictunnel уже импортирует relay, обратной зависимости нет) и применяется в двух местах, где идентификаторы отдаются санитайзеру: `identifyingMarkers` в шлюзе и proxy hostname в `sensitiveCredentialMarkers`. Секреты через фильтр НЕ идут — `credential.Value`, username, password отказывают при любой ширине (`TestAShortCredentialMarkerStillRefusesThroughTheGateway` — эта мутация выжила первый раз, потому что `TestShortCredentialMarkerFailsClosed` зовёт санитайзер напрямую и шлюза не видит; `TestAProxyHostTooShortToRedactIsNotAMarker` держит обе стороны).
- Цена этого решения названа в README прямо: короткий идентификатор, который модель упомянула в тексте, теперь проходит, а не отказывает ответ. Структурные поля переименовываются всегда, независимо от длины (`modelField` → publicModel, замерено: `"model":"o3"` → `"model":"fast"`, а «I am o3» в тексте остаётся). Не «забыли задокументировать» — это сознательный обмен слабой утечки на работоспособный туннель.
- Границы слов (`\b`) вместо отбрасывания короткого маркера — очевидная идея, и она хуже. Замерено: `\btor\b` действительно не ловит «constructor», а `\bo3\b` не ловит «foo3», но `\bai\b` по-прежнему отказывает «AI is useful» — обычную английскую фразу в продукте про AI, то есть класс отказа не закрыт. И одновременно ломается редакция длинных маркеров, где подстрочное совпадение выбрано намеренно: `\bSecretProvider\b` не совпадает с «SecretProviderX», а `\b::1\b` — с «host ::1 here», потому что `\b` вокруг пунктуации работает не так, как хочется. Ослабление редакции ради частичного лечения отказов — плохой обмен; не переделывать.
- Публичный tunnel работает fail-closed: allowlisted models only, sanitized headers/body/SSE, neutral errors, no `owned_by`, provider identity, upstream fields или membership oracle.
- Написание пути — не решение политики. Локальный relay отвечает своим `ServeHTTP`, а не через `ServeMux`, поэтому путь клиента никто не чистит: `/V1/Responses`, `/v1//responses` и `/v1/./responses` доходили до хендлера как есть, а девять мест сравнивали их сырым `TrimRight(path, "/")`. Замерено: `/V1/Responses` отдавал refusable payload со статусом 200 и нулём findings — и тем же написанием выключались folding tools (Codex-декларация), image/chat совместимость и диалект стрима, то есть relay молча становился обычным форвардером для этого запроса. Теперь все решения идут через `canonicalPath` (`path.Clean` + lower), а upstream по-прежнему получает собственную копию URL клиента без изменений (`TestPathSpellingCannotSkipInspection` — мутация до `TrimRight` роняет три написания). Публичный шлюз это не задевало: там exact-match allowlist, любое иное написание получает 404.
- Тот же лимит фрейма ловит и каталог моделей, и там правильный ответ — отказ, а не усечка. Замерено: 5000 имён по 43 байта занимают 87% фрейма, а 5000 по 50 (`anthropic/claude-3-7-sonnet-20250219:thinking-high` — ровно 50, обычное имя у агрегатора, не синтетика) не влезают вовсе, и Model Routes показывала «Command response is too large» — код, написанный про баг, на каталоге, который просто большой. Cap по количеству (`maxDiscoveredModels`) байты не ограничивает, поэтому проверка теперь байтовая (`oversizedCatalog` против `platform.MaxPayloadBytes`) со своим кодом `model_catalog_too_large`. Усекать нельзя: каталог — это список, ИЗ которого владелец публикует, и молча спрятанная модель есть модель, которую невозможно опубликовать; журнал находок в этом смысле противоположен — там усечка допустима, потому что записи только читают. Проект это решение уже принял в `gateway.go` (превышение количества тоже отказ), байтовая проверка лишь закрывает вторую единицу измерения (`TestALargeModelCatalogIsRefusedByNameRatherThanByFrameSize` — обе мутации: снятый guard и слишком жадный бюджет).
- Бан — это решение владельца, а решение, которое никуда не записалось, решением не является. Неудачную запись `SetProfile` отвергал и раньше, а вот отсутствующее хранилище было дыркой в том же правиле: бан применялся в памяти, список показывал его действующим, следующий запуск его молча терял — и туннель снова обслуживал адрес, забаненный в прошлой сессии, причём на экране ничто об этом не сказало. Теперь отсутствие хранилища — тот же случай, что и сбой записи: отказ доходит до UI по уже существующему пути ошибки, пока туннель ещё можно остановить. `LoadProfiles` по той же причине больше не возвращает «пусто» вместо «недоступно»: решений прошлых сессий не видно — это не то же самое, что их не было. Сообщение в bootstrap называет настоящую цену (баны не в силе и новые не сохранить), а не потерю телеметрии — база одна, но потери разные (`TestWithoutStorageABanIsRefusedRatherThanKeptInMemory`).
- Переписал тело — объяви возможность, от которой эта запись зависит. Профиль с часовым кэшем поднимал каждый `cache_control` до `"ttl":"1h"`, но `anthropic-beta` брался у клиента как есть. Клиент, который просит час сам, посылает вместе с ним `extended-cache-ttl-2025-04-11` (замерено — токен есть в бинаре Claude Code, дважды; токен по-прежнему в списке beta-идентификаторов доков и не в списке снятых), а Claude Code с обычным пятиминутным кэшем его не посылает — значит после апгрейда наружу уходил запрос, которого ни один клиент не формирует: тело просит час, заголовок молчит. Решает не «я поднял», а «тело несёт час»: апстрим читает заголовок, поэтому час, который клиент попросил сам и забыл объявить, объявляется тоже (первая версия правки проверяла факт апгрейда и на таком теле молчала — это нашёл собственный тест, а не рассуждение). Гейт бесплатный: `cache_control` — конструкция Anthropic, поэтому у Responses и Chat Completions поднимать нечего и чужая возможность им не приписывается. Заголовок клиента дополняется, а не затирается (Claude Code шлёт несколько beta), и правится копия — не то, что прислал вызывающий. Предел вложенности — единственный случай, когда relay молчит: там тело возвращается как пришло, никаких заявлений о нём не сделано (`TestTheHourIsDeclaredWheneverTheBodyCarriesIt`, 5 кейсов, 5 мутаций убиты тестом, а не компилятором).
- Логи структурированные и санитизированные. Хранят status, timing, queue/retry, token subsets и безопасные terminal details; никогда prompt, output body или credential.
- У stdio-протокола один лимит фрейма на обе стороны (`platform.MaxFrameBytes`, 256 KiB), и оценивать ответ надо в байтах, а не в записях. Шелл читает построчно и фрейм сверх лимита не просто отбрасывает — он выходит из цикла чтения и убивает sidecar, то есть всё приложение. Go никогда такой фрейм не пишет (`response_too_large`), поэтому падения нет, но у `guardrails.findings` расхождение единиц измерения было измеримым: один враждебный ответ несёт столько findings, сколько правил задел (замерено — 10), и 200 записей по 10 findings дали больше 256 KiB. Итог: страница находок недоступна ровно тогда, когда провайдер шлёт больше всего, а вернуть её можно было только уничтожив улики через `clear`. Теперь handler набирает записи под байтовый бюджет (`platform.MaxPayloadBytes` — одна константа платформы, потому что конверт фрейма добавляется поверх измеренного payload и знает об этом именно платформа; тем же бюджетом мерит каталог моделей, а инвариант «payload + конверт влезают во фрейм» проверяется один раз в `TestThePayloadBudgetLeavesTheEnvelopeItsRoom`), пропорциональной оценкой с проверкой, а не половинением. Усечка обязана быть видимой: метрика «Findings» берёт неусечённый `findingCount` из статуса, а подпись секции говорит «Newest N of M» (`TestTheFindingsTheWorkspaceAsksForFitInOneProtocolFrame`, `never reports a bounded findings list as the whole journal`).

## Guardrails

- Каждый ответ провайдера проходит локальную проверку перед тем, как клиент увидит байт. Slice `backend/internal/slices/guardrails` содержит правила (данные vendored из holone, MIT, атрибуция в `adapters/ruleset/LICENSE-holone.txt`), но движок написан здесь и не тянет зависимостей.
- Проверяется **финальное** тело в диалекте клиента, после всех трансляций и починок relay. Иначе payload спрячется в промежуточном диалекте, который relay ещё переписывал.
- Что проверять, решают путь клиента и сами байты, а не `Content-Type` от провайдера. Иначе враждебный апстрим помечает ответ `text/plain`, минует инспекцию целиком — и всё равно парсится любым клиентом, который читает тело, а не заголовок (`looksLikeEventStream` + `expectsJSONResponse`, тест `TestAMislabelledAnswerIsStillInspected`).
- Аргументы tool call приходят как JSON, а внутри JSON скрипт экранирован: `#!/bin/sh\ncurl x | sh` доходит до правила как `sh\ncurl` с литеральным backslash-n, и `\bcurl\b` не находит границу слова. Поэтому каждый накопленный кусок, который сам является JSON, отдаётся ещё и **расшифрованными строками** отдельным piece (склейка сырого с декодированным изобрела бы совпадение на стыке). Дубли findings режутся в `Inspector.Inspect` по rule+match+**вид места** (`sourceKind`), и обе половины ключа держат по тесту. Вид места нужен потому, что «где провайдер это положил» — и есть находка: `curl x | sh` в прозе честный ассистент выдаёт постоянно, тот же payload в аргументах tool call клиент вот-вот исполнит. Порядок pieces следует телу ответа, то есть выбирает его провайдер — значит при общем ключе именно атакующий решал бы, какая из двух атрибуций выживет, и поставил бы прозу первой (`TestThePlaceAPayloadWasPutIsNotDeduplicatedAway`). Вид грубый — все tool calls это одно место, а не одно на имя — иначе один payload, размазанный по сорока по-разному названным вызовам, занял бы все 32 слота `MaxFindings` и вытеснил **другой** high-детект (`TestOnePayloadRestatedAcrossManyToolCallsCannotCrowdOutAnother`). Сырая и декодированная половины одного вызова несут один вид, поэтому по-прежнему сворачиваются в одну (`TestOneToolCallIsReportedOnceDespiteBeingScannedTwice`).
- Диалект определяется формой, но форма — не контракт: одно поле не того типа (`arguments` объектом вместо строки) валит разбор всей схемы и уносит вместе с аргументами ещё и assistant text. Поэтому payload, который не понял ни один диалект, читается как plain JSON strings (`unrecognised`), и всё нераспознанное складывается в **один** аккумулятор — иначе поток чужого формата дал бы по piece на событие.
- Тело, которое не принял **наш** парсер, тоже читается — сырыми байтами (`unparsed`). `encoding/json` отказывает на 10000 уровнях вложенности, Python и JavaScript — нет, поэтому `{"choices":[…payload…],"pad":[[[[…20001…]]]]}` для клиента обычный Chat Completions, а для нас нечитаемое. Ранний `return` давал ноль pieces, ноль findings, чистый verdict и ни слова о том, что ничего не прочитано — полный обход в одну строку. Остаток берётся срезом по `InputOffset()`, а не через `Buffered()`: буфер декодера всего 64 KiB, и на теле длиннее он вернул бы фрагмент, а хвост ушёл бы непрочитанным молча. Плюс декодер читается в цикле: поток из нескольких объектов (`{…}\n{…}`, или объект с хвостом) — это и забытый SSE-фрейминг, и самый дешёвый тайник, потому что payload во втором объекте никто не смотрел. Закреплено `TestABodyOurParserRejectsIsStillInspected` (четыре формы, каждая мутацией).
- Дельты стрима склеиваются до сопоставления. Провайдер, разбивший `curl x | sh` на три события, обязан ловиться так же, как отправивший одной строкой. Внутри одного события `data:`-строки склеиваются через `\n` (так требует W3C), поэтому один перевод строки посреди payload тоже не обход: блоки режутся по `\n\n`, а не по `\n`.
- Тело больше буферного лимита инспектируется по прочитанному префиксу, а не пропускается. Обрезанные байты нельзя отдавать, но читать их можно, и пропуск проверки здесь продавал бы тишину за padding: провайдеру хватило бы добить ответ до потолка. Непрочитанный хвост при этом **докладывается** отдельным low-finding `proto-inspection-truncated` — «ничего не нашли» и «ничего не смотрели» для оператора разные вещи.
- Запись, у которой единственный finding — это `proto-inspection-truncated`, — бухгалтерия, а не детект, и провайдер выдаёт её на каждом ответе просто будучи многословным. В bounded store такие записи вытеснили бы все настоящие findings — это и был бы обход: добивай каждый ответ за budget, пока улика не свалится с конца списка. Поэтому такая запись хранится **одна на провайдера** и несёт `occurrences` и время последнего раза, занимая один слот вместо всех. Настоящие детекты не сворачиваются никогда: два одинаковых payload — это две попытки. Закреплено `TestPartlyReadAnswersNeverPushOutARealDetection`, `TestPartlyReadAnswersAreCountedPerProvider`, `TestRealDetectionsAreNeverFoldedTogether`.
- Инспекция идёт inline на response path, поэтому её цена — это ожидание клиента. 106 case-folded выражений, каждое сканирующее весь ответ, стоили 6.6 ms на килобайт и 4.2 s на потолке в 512 KiB. Движок выводит из каждого паттерна литералы, без которых он не может совпасть (`requiredLiterals` через `regexp/syntax`), и пропускает правило, если ни одного нет в ответе: 0.11 ms и 59 ms на том же железе, обычная проза не доходит **ни до одного** правила. Литерал длиной в один символ раньше отбрасывался как бесполезный — измерение это опровергло: `obf-caret-backtick` требует `^` или backtick, в прозе нет ни того ни другого, и это было единственное правило, которое всё-таки бежало, — все 81 ms из 81 ms. Пола на длину больше нет.
- Оптимизация только по времени, и это закреплено с двух сторон. `TestEveryRuleReportsAStringItsOwnPatternMatches` строит образец из AST каждого паттерна — по одному на ветку каждой альтернации, 643 образца на 106 правил — и требует, чтобы движок сообщил о правиле на строке, которую его же выражение матчит: неверно выведенный литерал молча выключил бы правило. `TestSkippingRulesByLiteralNeverHidesAMatch` проверяет обратное направление на случайном тексте — движок не должен сообщать о правиле, которое выражение не матчит; покрытия у него всего 16 правил из 106, поэтому он дополняет первый, а не заменяет. `TestOrdinaryProseReachesAlmostNoRule` держит саму цифру как счёт правил, а не как время, потому что у бенчмарка нет порога и CI бенчмарки не запускает. Всё недоказанное даёт `nil`, то есть «правило всегда работает».
- AST-генератор нашёл реальную дыру: `dl-certutil` перечислял восемь switch'ей, а матчил два. `\b` перед `-split` требует word-символа слева, поэтому ведущий дефис никогда не мог начать совпадение, и только у `urlcache` дефис был опциональным. `certutil -decode payload.b64 payload.exe` — обычный способ разложить payload — не детектился, а `certutil x-decode` детектился. Теперь switch должен идти после пробела, кавычки, скобки или `=`; rule set v7. Версия набора и число правил закреплены за фикстурой фронта (`TestTheFrontendFixtureCarriesThisRuleSet`) — она разъехалась молча, потому что на фронте её ни с чем не сравнивают.
- Режим по умолчанию `monitor`, не `block`. Правила совпадают с shell/network идиомой, которую честный ассистент выдаёт постоянно; блокировка по умолчанию убила бы легитимные ответы в первый день. `block` включает владелец для провайдеров, которым не доверяет.
- В блоклисте IOC локаторы и просто слова живут на разных severity. Домен, IP, hash и полный путь задачи принадлежат кампании и больше никому — `high`. `proxy.exe`, `CodeAssist`, `StartupOptimizer` — слова из честного ответа, и на `high` они в block-режиме отказывали бы в легитимной работе, поэтому `medium`. Кампанию всё равно ловят поведенческие правила: команда, которая создаёт такую задачу, матчится `high`.
- Tool call, которого клиент не просил, — не пограничный случай, а аномалия: запускать его нечем, значит вставил провайдер. Если запрос нечитаем, аномалия **не** выставляется (fail-open именно здесь): обвинение стоит легитимного ответа, а pattern-правила всё равно работают.
- Правила наружу не выходят никогда. UI и stdio отдают счётчики, категории и excerpt найденного, но не паттерны: отчёт не должен превращаться в инструкцию по обходу.
- Отказ — это потраченная попытка, а не мёртвый запрос. Правила совпадают с идиомой, которую честный ассистент выдаёт постоянно, и в `block` один неудачный ответ иначе убивал бы работу, которую отсюда не перезапустить. Поэтому запрос повторяется на том же бюджете, что у провайдера, упавшего громко (`PermanentAttempts`, `guardrailAttempts()`), и отказ остаётся в силе, если каждая попытка его заслужила: клиент payload не видит, он только ждёт дольше. Тело ещё не писалось, поэтому committed-стрим тоже перепрашивается — снаружи это headers и keep-alive, не контент. **Каждая** отклонённая попытка идёт в records: re-roll не стирает того, что провайдер пытался. `TestARefusedAnswerIsRetriedBeforeTheRequestIsGivenUp`, `TestAnAnswerRefusedEveryTimeIsStillRefused`, `TestMonitorModeNeverRetriesAnAnswerItRecords`.
- `Dispatch` (туннель) отказ **не** перепрашивает. Публичному клиенту re-roll дал бы N попыток на недоверенном провайдере, а туннель fail-closed по определению; снаружи отказ остаётся неотличимым от недоступного провайдера.
- Отказ уходит в туннель как обычная ошибка dispatch. Снаружи он неотличим от недоступного провайдера — ни по статусу, ни по телу, ни по заголовкам, ни по `errorCode` в истории клиента (`safeError` — allowlist, не blacklist).
- Guardrails есть в **обоих** изданиях. Публичный пользователь имеет то же право знать, что ему прислал провайдер. Это подтверждает `TestEditionAnswersOnlyItsOwnCommands`: он спрашивает `guardrails.status` у живого протокола и требует `guardrails.manage` в capabilities handshake.
- Данные vendored, значит нотис едет с ними: `LICENSE-holone.txt` попадает в оба инсталлятора как `bundle.resources` (в NSIS — рядом с exe, в deb/AppImage — `usr/lib/Luxury Switchboard/`). Правила встроены в бинарь через `go:embed`, а лицензия MIT требует нотис в каждой копии. Наши правки vendored-данных перечислены в поле `note` файла `rules.json` вместе с версией набора — сейчас v6: `fs-alternate-data-stream` требует `-Stream` или настоящий ADS-редирект вместо голого `ads` и вместо любого TypeScript-алиаса; добавлено `obf-decode-pipe-exec` (`base64 -d | sh`, `FromBase64String | iex` не ловились ничем); и семь правил сужены, потому что на `high` они отказывали в обычных ответах разработчика — `npm install eslint-plugin-import`, `type Result<T> = ...`, DevTools про cookies, слова `Stop`/`Notification`, `runPending()`, ссылка на доки рядом с `.bashrc` или `CLAUDE.md`. Обе стороны закреплены тестом `TestOrdinaryDeveloperAnswersAreNotRefused`: честная строка не блокируется, атака того же правила блокируется.
- Режим — persisted setting, но применяется на следующем запросе, а не после restart (`settingsService.OnApplied` → `Inspector.SetMode`, `Settings.RequiresRestart` игнорирует это поле). Новое поле настроек обязано попасть в `Normalized()`, иначе файл прошлой версии не пройдёт `Validate()` и молча сбросит всю конфигурацию пользователя.

## Definition of done

- Реальный основной сценарий работает, а не только компилируется.
- Затронутый slice имеет domain/unit tests и adapter/integration coverage; критичные stdio, relay streaming, retry, cancellation, persistence и privacy boundaries имеют end-to-end tests.
- Go проходит format, vet, tests и race checks для конкурентного кода. Frontend проходит typecheck, lint, tests и production build. Tauri bundle собирается из проверенных sidecar bytes.
- UI проверен кликами и скриншотами на заявленных размерах; визуальный концепт и финальный render сравнены напрямую.
- Live relay gate включает sequential + parallel large-context запросы, long reasoning/SSE terminal completion, cancellation/provider switch и image path на соседнем loopback-порту.
- Перед commit проверяются diff, секреты, артефакты, package manifest и отсутствие оставшихся test listeners/processes.

## Editions

- Продукт собирается в двух изданиях из одного дерева: `owner` (полное) и `public` (для обычных пользователей). Публичное издание не содержит public tunnel, tunnel clients и shared control.
- Вырезание обязано быть физическим, а не косметическим. Go-код владельца живёт за build tag `public` (`edition_owner.go` / `edition_public.go`), поэтому в публичном бинаре нет ни handler'ов, ни SSH-publisher, ни hub-клиента: запуск sidecar вручную не открывает эти команды.
- Frontend режется тем же принципом: ветки, которые должны исчезнуть из бандла, проверяют литерал `__OWNER_EDITION__` прямо на месте (`App.tsx`, `ServicesProvider`, `navigation.ts`), иначе bundler не удалит модуль — `navigation.ts` ветвился на реэкспорт и тянул в публичный бандл иконки owner-вкладок. Читаемый `OWNER_EDITION` из `app/edition.ts` используется там, где нужен только runtime-выбор.
- `pnpm backend:check` прогоняет тесты обоих изданий, и CI обязан прогонять `-tags public` тоже. Без этого `TestEditionAnswersOnlyItsOwnCommands` в автоматике проверяет только owner-ветку, а утёкшая в публичный бинарь команда уезжает незамеченной. Тест спрашивает у реального протокола, что издание умеет, и обязан оставаться правдой для обеих сборок.
- Allowlist в `src-tauri/src/sidecar.rs` один на оба издания намеренно: shell решает только, достаточно ли фрейм корректен, а существует ли команда — ответ sidecar, и публичный собран без этих handler'ов, поэтому owner-метод возвращает `method_not_found`. Разделение списка купило бы другую строку ошибки, не границу.
- `system.handshake` возвращает `edition` и capabilities этого издания. UI не должен предлагать сценарий, которого нет в ответе handshake; новая вкладка добавляет свою capability, иначе handshake врёт про то, что бинарь умеет.
- Новый owner-only сценарий добавляется сразу в оба места: за build tag в Go и за `__OWNER_EDITION__` во frontend; иначе публичная сборка получит мёртвую вкладку или живую команду.
- `pnpm build` и `pnpm build:linux` собирают оба издания: owner в `artifacts/release`, public в `artifacts/release-public`, у каждого свой `SHA256SUMS.txt`. Релиз падает, если в публичном бандле остались owner-чанки или в публичном sidecar нашлись owner-команды.
- Публичный артефакт несёт метку издания в имени: `Luxury-Switchboard-<version>-public-windows-x64-setup.exe`. Оба инсталлятора делят bundle identifier и путь установки, поэтому публичный молча заменяет owner-установку — при одинаковых именах после скачивания их не различить ничем, кроме папки. Имя owner-артефакта остаётся без метки: его называют корневой `SHA256SUMS.txt` и `package-friend.ps1`.
- Коллектор релиза забирает из `src-tauri/target/release/bundle/` только файлы, записанные текущей сборкой (по mtime). Там лежат инсталляторы всех прошлых версий и прошлых названий продукта; отбор по одному имени однажды нашёл два кандидата на `1.0.8`, а хуже был бы один — тогда релиз молча увёз бы бинарь недельной давности.
- CI поднимает и складывает **обе** папки изданий. Корень artifact'а — `artifacts/`, а не `artifacts/release`: иначе public-инсталлятор собрался бы и был выброшен, а job `collect` упал бы на `--checksums-only`, потому что тот пишет суммы для каждого издания и требует непустую папку.

## Product name

- Продукт называется **Luxury Switchboard**. Так он подписан в `tauri.conf.json` (`productName`, заголовок окна), в sidebar, в `frontend/index.html`, в описании крейта и в именах артефактов (`Luxury-Switchboard-<version>-...`).
- Внутренние идентификаторы это переименование **не** трогает и трогать нельзя: bundle identifier `one.luxuryprivate.switchboard`, Go module path, каталог данных `ProviderSwitchboard`, DPAPI/keyring entropy и заголовки `X-Switchboard-*`. Смена любого из них теряет сохранённые ключи и конфиг пользователя.
- `productName` — не косметика: NSIS кладёт по нему каталог установки (`$LOCALAPPDATA\<productName>`) и ключ удаления. Переименование не обновляет прошлую установку, а создаёт вторую рядом: два ярлыка, один каталог данных, один порт. Инструкция в `FRIEND-SETUP.md` обязана говорить снести старую запись, пока хоть у кого-то стоит сборка с прошлым именем.

## Release version

- Версии **только патчевые**: линия навсегда `1.0.x` — `1.0.7`, `1.0.8`, … `1.0.105`. Никаких minor и major (`1.1.0`, `1.3.0` — ошибка, которую уже пришлось откатывать). Любое изменение, которое уходит пользователю, поднимает патч на один.
- Версия не набирается руками. `pnpm version:set 1.0.8` (или `pnpm version:set` — инкремент патча) пишет её во все шесть мест: `src-tauri/tauri.conf.json` (источник истины для bundle и имён артефактов), `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` (пакетная строфа `switchboard-desktop`), `package.json`, `frontend/package.json` и `AppVersion` в `backend/internal/slices/system/adapters/stdio/register.go`. Список мест живёт один раз в `scripts/version.mjs`; забытый lockfile даёт дерево, которое gate считает согласованным, а `cargo --locked` отвергает.
- UI никогда не хардкодит версию. Sidebar показывает то, что вернул `system.handshake`, то есть Go `AppVersion`, который проставила сборка; новые места отображения берут её оттуда же. `App.test.tsx` держит это правдой.
- `pnpm build` и `pnpm build:linux` падают до сборки, если значения разошлись или версия не патчевая (`assertVersionsAgree` и `assertPatchOnly` в `scripts/version.mjs`). Не обходить проверку, а прогнать `pnpm version:set`.
- Новая версия попадает в commit вместе с изменениями. Корневой `SHA256SUMS.txt` содержит ровно одну строку — контрольную сумму собранного owner-инсталлятора из `artifacts/release`, её проверяет `scripts/package-friend.ps1`. Папки изданий получают свои `SHA256SUMS.txt` от сборки; чужие артефакты удаляются автоматически.
- Новая stdio-команда добавляется одновременно в Go handler и в allowlist `src-tauri/src/sidecar.rs`; расхождение ловит `TestEveryControlPlaneCommandIsAllowedByTheDesktopShell`.
