# Engineering rules

- Никаких монолитов. Новый функционал нельзя складывать в один растущий файл, класс или god-object.
- Архитектура проекта — hexagonal: доменная логика не зависит от TUI, HTTP, SQLite, SSH и других инфраструктурных адаптеров.
- Разработка ведётся vertical slices: один пользовательский сценарий содержит собственные UI/application/domain/adapter части и тестируется сквозным образом.
- Зависимости направлены внутрь: UI и инфраструктура вызывают application/domain ports, но домен не импортирует внешние фреймворки.
- При изменении существующего монолита нужно выносить цельный рабочий срез, а не добавлять ещё один wrapper или абстракцию без самостоятельной ответственности.
- Общий код выделяется только после появления реального повторения; безопасность, валидация границ и отмена запросов не упрощаются.
